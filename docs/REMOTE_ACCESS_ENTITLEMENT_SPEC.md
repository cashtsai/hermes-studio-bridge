# 遠端存取付費架構規格（relay 訂閱制）

> 機主 2026-10-29 拍板三題：**賣 relay 服務訂閱**（QR 登入免費）、**無帳號**
> （收據綁裝置）、**遠端維持擋檔案面**（其餘全開）。
> 本文件是實作依據 —— **改實作先改這裡**。狀態：**規格，未實作**。
>
> 相關：`CONSOLE_QR_LOGIN_SPEC.md`（認證機制）、
> `POCKET_SERVICE_PRICING_HANDOFF.md`（拓撲現況與產品化目標、Dedicated Lobster）。

## 0. 一句話

**付費買的是「可達性」，不是「功能」** —— 你的 Mac 在公網上被找得到這件事有真實
伺服器成本，所以收費；而「怎麼安全地登入」（QR + 手機批准）永遠免費。

## 1. 為什麼這樣切（三個理由）

1. **誠實**：relay 是一台要付錢的機器，賣它是賣服務。把「登入方式」收費、同時
   留一個較弱的免費登入法，是反的。
2. **審核好過**：賣「我幫你維運一條公網入口」比賣「解鎖 app 內功能」容易說明，
   也不會變成「同樣的程式碼擋住不給用」那種觀感。
3. **技術上本來就是這樣**：沒有 relay，非 tailnet 的瀏覽器**根本碰不到**你的
   bridge（NAT 後面）。QR 登入在 LAN/tailnet 下免費可用，到了公網需要的是
   「有人幫你轉送」—— 那才是成本所在。

### 免費 / 付費邊界（寫進 UI，不要讓人猜）

| 情境 | 需要 relay? | 收費 |
|---|---|---|
| 同機 `127.0.0.1` 開控制台 | 否 | **免費** |
| tailnet 直連開控制台 | 否 | **免費**（使用者自己的 Tailscale） |
| QR 登入機制本身 | — | **免費**（安全機制不收費） |
| **從任意電腦（公網）開控制台** | **是** | **訂閱** |
| 手機 app 的一切既有功能 | 現狀 | **免費**（不得退步，見 §6） |

## 2. 「真的到哪裡都能用」還缺什麼（誠實的缺口清單）

QR 登入只解決了**授權**。要真的「到哪裡都能用」，缺的是這些：

| # | 缺口 | 現況 | 嚴重度 |
|---|---|---|---|
| G1 | **多租戶 relay** | `gateway.shan.house` 是**單租戶**（Caddy → 機主自己的 bridge）。pricing 文件自己寫「尚未完成獨立的多租戶 connector daemon」 | **阻擋**：沒有這個就只有機主能用 |
| G2 | **Mac 睡著** | 睡了就什麼都連不到。這是「到哪裡都能用」**最常見的實際破功原因**，比任何程式缺陷都常見 | **高**（見 §7） |
| G3 | **bridge 離線時的誠實狀態** | 現在的失敗長得像「連線失敗」，分不出「你的 Mac 睡了」vs「relay 掛了」vs「你沒訂閱」 | 高 |
| G4 | **entitlement 要在三個地方被認得** | 完全沒有（`SubscriberGate` 是 fail-open 的殼） | **阻擋** |
| G5 | **無帳號 → 跨平台不通** | iOS 買的 Android 不認 | 中（§5 要在 UI 講清楚） |
| G6 | **審核員無法驗證** | 他沒有你的 Mac，訂閱價值無法示範 | **阻擋上架**（見 §8） |
| G7 | **流量成本無上限** | relay 轉送檔案/終端機流量，成本隨用量走 | 中（§9） |

> G1 與 G4 是「沒有就不能賣」；G6 是「做了也上不去」。這三個要先排。

## 3. Entitlement 架構（無帳號怎麼做到）

### 3.1 核心洞見

**手機已經是授權者了** —— QR 登入就是「手機批准瀏覽器」。所以讓**同一支手機
順便當 entitlement 的攜帶者**，不需要任何帳號或使用者資料庫。

```text
手機:StoreKit 購買(綁 Apple ID,不建帳號)
      ↓ Transaction.currentEntitlements 裝置端驗證
手機:批准 QR 登入時,一併聲明「我有 relay 訂閱」
      ↓ POST /app/v1/console/login/requests/{rid}/approve  { "relay_entitled": true }
bridge:記在這筆 login request 上
      ↓
relay:只替「有 entitlement 的 bridge」轉送
```

### 3.2 三個執行點

| 執行點 | 檢查什麼 | 失敗時 |
|---|---|---|
| **手機 app** | `Transaction.currentEntitlements` | 顯示訂閱頁。**只擋「產生公網 QR」這一個動作**，其餘功能一律放行 |
| **bridge** | 批准時手機聲明的 entitlement | 非付費 → QR 登入只在 LAN/tailnet 可用（公網請求回「需要訂閱」而非 403） |
| **relay** | 這個 bridge 有沒有在付費名單上 | 不轉送，回可讀的 402/503 頁說明 |

### 3.3 relay 端的最小伺服器狀態

**不是使用者帳號**，是「bridge 可達性授權」：

```json
{ "bridge_id": "<bridge 公鑰指紋>", "paid_until": 1764000000, "plan": "relay-basic" }
```

- 只有 `bridge_id` + 到期時間，**沒有姓名、Email、Apple ID、購買記錄**。
- 怎麼寫進去：手機帶著 StoreKit 收據去 relay 註冊自己配對的 bridge。
  relay 用 **App Store Server API** 驗收據真偽（這是唯一需要伺服器側驗證的地方
  —— 因為 relay 的資源是我方成本，不能只信客戶端）。
- 收據 ↔ bridge 綁定：一份訂閱可綁 N 台 bridge（建議 N=3，夠一家人/多台機器，
  又擋住把訂閱當公用代理轉賣）。

### 3.4 一個刻意的工程判斷：客戶端檢查足夠的地方就別上伺服器

**app 端的 entitlement 檢查是可以被破解的**（改 app 就繞過）。這裡刻意接受，理由：

- 繞過的人是**那台 Mac 的主人**，他要存取的是**自己的機器**。
- 技術上有能力改 app 的人，直接裝免費 Tailscale 就能達到同樣效果 ——
  **作弊的收益低於作弊的成本**。
- 真正會燒錢的是 relay 流量，而 relay 是**伺服器側驗證**（§3.3），破不了。

所以：**app 端用來決定「要不要顯示訂閱頁」，relay 端才是真閘。**

## 4. 絕對不能發生的事：把人鎖在自己的機器外面

`NoMonetizationSurfaceTests` 已經寫下這條原則：
> 「功能閘門在收費暫停時一律放行 —— **不得留下「升級才能用」的死路**」

付費上線後這條**不廢除，只縮小適用範圍**：

1. **tailnet / loopback 永遠免費**，任何 entitlement 狀態都不得影響。
   這是「鎖不死」的根本保證 —— 使用者永遠有一條不經過我方、不花錢的路。
2. **計費系統故障 = 放行**（fail-open）。收據驗不到、relay 的授權 DB 讀不到、
   App Store Server API 掛掉 → **當作有訂閱**。寧可送出幾小時免費流量，
   也不要讓付過錢的人連不上自己的 Mac。
3. **寬限期**：訂閱到期後 **7 天**仍可用，期間顯示續訂提示。
   Apple 的續訂重試本身就可能跨好幾天，到期即斷會冤枉人。
4. **已開啟的 session 不中斷**：entitlement 在 session 存續期間失效時，
   讓當前這條連線做完（最多到 token 到期），不要在使用者打字時斷線。

> 這四條要有對應測試，並且**改寫**（不是刪除）`NoMonetizationSurfaceTests`：
> 從「付費牆恆關」改成「付費牆只影響公網可達性，其餘一律放行 + fail-open」。

## 5. 無帳號的代價：必須說清楚

跨平台不通是**選擇無帳號的直接後果**，不是 bug。要在三處明說：

1. **訂閱頁**：「此訂閱在這支裝置的 App Store 帳號下有效。Android 版需另外訂閱。」
2. **Android 訂閱頁**：同款反向文案。
3. **FAQ / 商店描述**：避免「我在 iPhone 買了為什麼 Android 要再買」的客服量。

> 要改成買一次兩邊通，就必須建帳號 → 重新打開 **5.1.1(v)**（1.0.0 被退的那條）
> + 公開上線的隱私政策（現寫 "Private mode — no account at all"）要改寫
> + 必須實作「刪除帳號」。機主已拍板**不走這條**。

## 6. 不得退步（migration safety）

現在能用的東西，**付費上線後一件都不能變成要付費**：

- 手機 app 的全部既有功能（聊天、CC/CX、核准、分享擴充…）
- tailnet / loopback 的桌面控制台
- QR 登入機制本身

**唯一新增的收費項是「公網可達性」這個本來就不存在的能力。**
這一條要寫進測試：既有功能的閘門在任何 entitlement 狀態下都必須放行。

## 7. Mac 睡著（G2）—— 最容易破功、也最容易被忽略

使用者在外面打開瀏覽器，Mac 在家睡覺 → 一切白做。這不是程式缺陷，但它會
讓「到哪裡都能用」這句話在**現實中大部分時間是假的**。

處置（依成本排序）：

1. **先做誠實狀態**（§G3）：relay 分得出「bridge 沒連上來」，要回
   「**你的 Mac 目前離線或休眠**」+ 一句怎麼辦，不要回通用的連線失敗。
2. **安裝時就講**：relay 訂閱的說明頁要寫明「需要你的 Mac 保持開機且不休眠」，
   並提供一鍵指引（系統設定 → 節能 → 防止休眠 / `caffeinate` 的說明）。
   **賣之前先講清楚前提**，不然就是賣一個大部分時間不能用的東西。
3. （後續）**Wake on LAN / Power Nap 探索**：bridge 可在睡前註冊一個喚醒管道。
   未驗證可行性，列為研究項，**不寫進第一版的銷售承諾**。

## 8. 審核風險（G6）：訂閱價值無法被審核員驗證

**這是最可能擋下上架的一項，而且不是技術問題。**

審核員拿到 app，沒有你的 Mac、沒有 bridge、沒有 relay 授權。他按下訂閱按鈕
之後**看不到任何東西發生** —— 這在 App Review 眼中接近「訂閱沒有提供可驗證的
價值」，而且 app 已經被 5.1.1(v) 退過一次，不該再給他們第二個理由。

處置（三件都要做）：

1. **示範模式必須涵蓋這條路**：app 已有 `DemoMode`。訂閱頁在示範模式下要能
   走完整個流程並顯示一個**假的但完整的**遠端控制台畫面，讓審核員看得到買的是什麼。
2. **送審備註（`docs/appstore/REVIEW_NOTES.md`）新增一節**：說明這是
   「使用者自備 Mac + 我方維運的公網轉送服務」，並提供一組**可用的測試憑證/
   測試 bridge**讓審核員實測。沒有這個，審核員只能猜。
3. **商店描述與訂閱 metadata 明寫前提**：「需要一台你自己的 Mac 執行 Pocket
   Bridge」。前提寫在購買前，不要寫在購買後。

## 9. 流量與成本（G7）

relay 轉送的是終端機/卡片流/檔案上傳，成本隨用量走。第一版：

- **公平使用上限**（建議每月 N GB，N 待定），超過降速而非斷線。
- 上限與目前用量要在 app 內看得到 —— 使用者不該在被降速時才知道有上限。
- **不做按量計費**：心理成本太高，會讓人不敢用。

## 10. 實作順序（依「沒有就不能賣」排序）

### 第 0 階段：先把 QR 登入做完（前置）
見 `CONSOLE_QR_LOGIN_SPEC.md` §16：入口分流 + token scope（擋 `/file`、
`/filediff`）+ iOS/Android 批准頁。**這一階段完全不碰收費**，而且就算收費
永遠不做，它本身也有價值（tailnet/LAN 的 QR 登入比六碼好用）。

### 第 1 階段：多租戶 relay（G1，最大的工程）
bridge 註冊 → relay 依 `bridge_id` 路由 → 授權名單查核 → 離線狀態誠實回報。
這是獨立的伺服器工程，**不在 bridge repo**，需要自己的規格。

### 第 2 階段：entitlement 三執行點（G4）
1. relay 側授權 DB + App Store Server API 收據驗證（**真閘**）
2. bridge 側讀手機聲明
3. app 側 `SubscriberGate` 實作 + 翻 `PaywallPresenter.iapHidden`
   + **改寫** `NoMonetizationSurfaceTests`（§4）

### 第 3 階段：上架前置（G6）
示範模式涵蓋、送審備註、商店描述、隱私政策的 Network connections 補
`gateway.shan.house`（上一輪稽核已補過 Cloudflare tunnel 與
`pocket.tsai.cash`，這條是新的，**漏了就是不實陳述**）。

### 第 4 階段：Android
Play Billing + 批准頁，照 `IOS_PARITY.md` 流程追。

## 11. 待決

2. **一份訂閱可綁幾台 bridge**（建議 3）。
3. **Dedicated Lobster**（`POCKET_SERVICE_PRICING_HANDOFF.md` §4.5，每人一台 VM）
   與本文的 relay 訂閱是**兩個不同產品**還是同一階梯的高階方案？
   這題會影響 relay 要不要設計成可升級到專屬 VM。
4. **第 1 階段的 relay 要自建還是用現成**（Cloudflare Tunnel 的多租戶方案 /
   Tailscale Funnel 代管 / 自己的 Caddy 艦隊）—— 影響成本結構與工程量。

## 附：這份規格刻意**沒有**承諾的事

- 不承諾「Mac 睡著也能用」（§7 第 3 點是研究項，不是功能）。
- 不承諾跨平台一次購買（§5，無帳號的直接後果）。
- 不承諾遠端檔案瀏覽（機主拍板擋檔案面；見
  `CONSOLE_QR_LOGIN_SPEC.md` §9）。
- 不承諾按量計費或無限流量（§9）。

**銷售文案不得超出這個清單。** 賣超過能力範圍的東西，退款與負評的成本遠高於
多賺的訂閱。
