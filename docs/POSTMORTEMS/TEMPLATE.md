## Impact

<誰受影響、從什麼時候到什麼時候、怎麼被發現的。

寫**使用者症狀**,不是 stack trace:「進 session 卡死在『連線中斷,正在補接』,

## Root cause

<結構性的那一句話。

合格的形狀:「型別表達力不足,所以兩個不同 process 的事實被接在一起」、
「同一個問題有兩個答案,於是漂移」、「契約被壓縮成一個子字串」、
「這個格子沒有擁有者」。

**不合格:任何以人為終點的結論。** 「某人忘了」「review 沒看到」
「當時很趕」都不是根因 —— 那是症狀。繼續往下問一層:
*什麼東西讓『忘了』這件事有可能發生,而且不會被任何機制發現?*>

## Guardrails added

<**每一條都要是已經 commit 的閘門**,附路徑與 commit sha。

判準:「把修復 revert 掉,這條會紅嗎?」答不出「會」就不是 guardrail,刪掉它。

「下次注意」、「加進 backlog」、「文件補了一段」**一律不算**
(文件若同時有機械閘在驗才算,寫出那支閘)。
