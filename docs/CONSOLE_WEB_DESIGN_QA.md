# Pocket Console Web：接力與閱讀驗收

適用於 CC、CX 維護 Web Console。這是人工選用的瀏覽器走查，不是 iOS 規範或發版門檻。借用 [Taste Skill](https://github.com/Leonxlnx/taste-skill) 的做法：每次選一項工作、用真瀏覽器操作、保留變更前後的證據。不安裝 plugin、Stop hook 或更動品牌規則。

## 第一輪：接回正在跑的 CX

問題：已登入的人能否找到剛在手機使用的同一條對話，讀上一段時不被串流拉走，並分辨訊息有沒有送到？本機情境用同時存在的 CX、CC 工作用來辨認，沒有模擬掃碼配對。只有 CX 開啟並接收串流。

以 `75686b3` 的 Console 靜態資產、Chrome 156 一般分頁、80 則合成歷史重播。2026-11-10 實測：

| 已登入後的操作 | 1366×768 | 820×1180 | 390×844 |
| --- | --- | --- | --- |
| 從最近工作點進指定 CX | 1 次 | 1 次 | 1 次 |
| 頁面無水平溢出、輸入及送出可點 | 通過 | 通過 | 通過 |
| 往上滑 320px，新卡進來後原文位移 | 0px | 0px | 0px |
| 往上滑 48px，新卡進來後原文位移（容許 8px） | **−154px** | **−154px** | **−154px** |
| 離線未送、已排隊、主機已收到、送達不明提示可見 | 通過 | 通過 | 通過 |
| 點「確認送達」讀取卡片、無新增 POST | 通過 | 通過 | 通過 |

**舊版原因。** `renderCards` 曾以距底部不足 80px 決定跟隨，48px 因此被當成仍在底部。

**區分請求與執行。** 測試主機收完訊息便切斷連線、不給收據。該次單擊在三個尺寸分別留下 5、4、4 個 HTTP POST，但同一尺寸內每個 POST 的內容與 `client_id` 都相同。這是斷線注入下的觀察，不是正式流量或模型執行次數。之後按查詢只有 GET。另跑 bridge 現有的兩個 `same_client_id` 回歸均通過。這些證據不等同外網斷線端到端驗收。

## 捲動修後複驗

2026-11-10，同樣的三種 Chrome 視窗、同一份合成歷史，更新後的 `renderCards` 記住閱讀狀態，不再讓新卡決定是否恢復跟隨。

| 操作 | 三種尺寸的實測結果 |
| --- | --- |
| 開啟 CX，第一則串流回覆進來 | 開啟時在最新處，更新後距底部 0px |
| 各自從底部上滑 4、48、320px，加入一則新回覆 | 9 次原文位移皆為 0px（舊版 48px 情境位移 −154px） |
| 各自手動捲回底部，再加入一則新回覆 | 9 次皆恢復跟隨，距底部 0px |

常規瀏覽器回歸另外覆蓋：在合成 CC 上滑後新增卡、按「更早訊息」都不移走正在讀的訊息；切到另一個 CX 時從最新處開始，不繼承前一條對話的閱讀位置。

## 新回覆提示與輸入量測

上滑後收到一般文字回覆才顯示「有新回覆 ↓」；只上滑、工具執行、純思考文字、使用者回聲都不算。按鈕或手動滑到底會恢復跟隨；切換對話不保留提示。這只記在目前頁面，不是跨裝置已讀或閱讀位置。三種寬度同驗提示是否可點、文字完整，以及仍能留在原文。

診斷：`POCKET_QA_TYPING=1 node --test tests/browser/console-typing-probe.cjs`。800 張已載入的合成卡，Chrome DevTools 輸入法組字並確認中文 40 次；各段驗證草稿沒有漏字或誤送。在空閒及每 50ms 更新同一張回覆卡時，分別量 input 事件時間戳到第二個動畫影格。這是瀏覽器可重現的延遲指標，不是實機鍵盤或螢幕實際顯示時間；不要設跨機種固定 CI 門檻。

2026-11-10 最終本機樣本：空閒 p95 約 225ms，串流 p95 約 157ms；各 80 筆。多次重跑數值有變化，不能說串流提高效能，也不能以此歸因給十秒清單輪詢。以 CSS 原生輸入框自動調高取代既有排版未見穩定改善，未採用。下一步拿低階 Chromebook 實測，並以 trace 分開檢查輸入處理、排版與清單刷新。

## 重跑與交接

需要能載入 Playwright 的 Node 環境（若安裝在工具目錄，用 `NODE_PATH` 指定其 `node_modules`）與已安裝的 Chrome。從 repo 根目錄執行：

```sh
POCKET_QA_READING_PILOT=1 POCKET_QA_SCREENSHOTS="$(mktemp -d -t pocket-console-qa)" \
  node --test tests/browser/console-reading-pilot.cjs tests/browser/console-handoff.cjs tests/browser/console-workstation.cjs
```

要保留結果可將 `POCKET_QA_SCREENSHOTS` 改為指定的本機資料夾。閱覽 `<寬度>.json`、`<寬度>-read-48-before.png` 與 `-after.png`；送達狀態另有獨立截圖。任一尺寸超過位移容差會回傳非零。未指定試點旗標時，三尺寸走查略過，一般接力回歸仍執行。

新的畫面只選一個主要操作，先寫預期，再重播現有合成 fixture；PR 列出版本、尺寸、實測差異和一組前後圖。保留 Pocket 的元件、字體、品牌色和手勢。兩個 UI PR 後再判斷是否納入例行檢查。不把憑證、私人 session 或真實工作截圖放進交接。
