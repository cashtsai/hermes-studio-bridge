# Pocket 網頁接力：開發與驗收清單

盤點：2026-11-08。對象：Console 前端、bridge、Pocket 手機端與 QA 維護者。

**使用者故事：** 我在手機上做到一半，走到另一台電腦。不安裝軟體、不加入私人網路、不登入 AI 供應商，開一個 Pocket 網址、用已配對的手機掃碼核准，就能找到同一份工作、回覆或處理待辦。登出這台電腦後，工作仍在原主機繼續。自己的 Chromebook 則可以把同一個網頁裝成獨立視窗。

**產品界線：** 這是現有 Console 的精簡使用方式，不是第二套 App、瀏覽器擴充功能、遠端桌面或雲端執行環境。Chrome 帳號不是 Pocket 的授權。首版保證 Claude Code、Codex 的既有 session；人格對話沿用已有能力，其他 provider 不宣稱完整支援。主機必須在線，受管理電腦仍須允許連線。對於真正不可信或遭監控的電腦，不宣稱掃碼能保護螢幕及鍵盤內容。

## 可以指派的工作單

2026-11-08 第一批進度：W01 已由開發機確認主機專屬 relay 的未登入回應是 403 `local only`，私網為 401；未開正式公網入口。W02 已在獨立工作樹 `bridge-web-relay-first-slice` 完成第一批修正與隔離測試，見該分支的 `docs/CONSOLE_BORROWED_BROWSER.md`。正式 Chromebook 與手機端驗收尚未完成，兩項先不勾選。

2026-11-08 第二批進度：同一工作樹已完成 W03 的分 session 草稿、單次派送、遺失回應後唯讀查收據，及 W04 的即時事件讀取、續傳游標、410 冷載和並發核准保護。Chrome 故障注入與隔離後端測試已通過；W03/W04 保留待實機三端驗收，正式環境授權未變更。

2026-11-08 第三批進度：W05 工作首頁已在獨立工作樹接上主機活動時間、待處理核准、專案或 ID 搜尋與全部工作。36 條含同名的合成對話已在新 Chrome profile 驗證；CC 無已知活動時間仍可搜尋，不宣稱能讀取手機最後停在哪一頁。未部署。下一批 W06 先核對遠端授權涵蓋的 HTTP 方法與子路由，再依權限收斂畫面；公網 Chromebook／手機實機仍待驗。

2026-11-08 第四批進度：W06 已在同一獨立工作樹將原路徑前綴白名單換成「方法＋操作＋此瀏覽器可見的 session 能力」。借用電腦隱藏主機工具，工作區變更預設關閉，核准與原 session 綁定；新增直接打 API 的越權測試及正常 Codex 派送驗證。未部署、未撤銷。下一步為測試主機上 W01/W08 的真手機、外網 Chromebook、原生 CC/Codex 三端演練。

未勾表示**仍需交付或拿到驗收證據**，不代表底層功能不存在。依序先跑 W01；其餘 P0 可分工。任何修正集中在既有 API 或 Console，不另建 history、retry 或 provider session 系統。

- [ ] **W01 / P0 / QA + relay：走通外網入口，先驗再開發。** 用非私網的新 Chrome profile，從同一個可記住的產品網址開始；由手機授權選中的主機，已登入或受信任的主機專屬連結仍可直達。同時核對既有公網中繼、私網短碼及 QR 的分流順序。如果已有通用入口，記錄並直接用；若只有每台主機各自的 URL，才開最小的入口與配對請求轉送，不集中代理聊天記錄。驗收：兩位測試使用者各連自己的主機；網址不含憑證、不洩漏主機清單。QR 過期、拒絕、主機離線都能清楚退出或重試，不改走權限更大的登入。
- [ ] **W02 / P0 / bridge + Console + iOS：公共電腦的安全離席。** 顯示「登出這台電腦」，手機能辨識並撤銷單一瀏覽器。沿用裝置撤銷，不撤其他裝置或停止 agent。現有 bootstrap 會從 localStorage 取 bearer；SW 會快取導覽回應。檢查完整生命週期而非只清畫面：臨時憑證不長存、敏感與登入頁不快取、既開串流能失效、多分頁同步登出。驗收：同一 Chrome profile 登出後按上一頁、離線重開或還原分頁看不到前人對話；舊授權不能再讀、送或核准。忘記登出可用手機撤銷；網斷無法確認撤銷時不顯示「已撤銷」。臨時授權逾時；不倚賴關窗通知。
- [ ] **W03 / P0 / Console + bridge：回覆只執行一次，不能串到別條。** 沿用現有 session ID 與 client_id，將一次送出、重試和對帳綁到同一 ID；目前 sendInput 每次呼叫會新建 ID。非成功回應要與空資料分開。慢網從 A 切 B 時，A 的快照、附件、草稿、送出結果和串流不得寫到 B。驗收：丟掉已受理的 HTTP 回應後按重試，手機、Web、原生端各只見一則輸入、主機只執行一次；連按送出亦同。不支援安全重送時顯示待確認，不能默默重發。
- [ ] **W04 / P0 / Console + bridge：中途換裝置能追上現場。** 用既有 snapshot、since_seq 和 410 冷載；目前重連重用建立串流時的 URL。斷線時如實呈現，重連從已套用的游標補齊。驗收：運行中關分頁、斷網 30 秒再開、手機先回覆，Web 都回到同一條且不漏最後一張卡；舊游標失效也不重開任務。手機與 Web 同時處理同一核准僅能生效一次，逾時或已處理不可再按。
- [ ] **W05 / P0 / Console：登入就找到「剛才那件事」。** 在現有側欄與快速面板上增加「繼續工作」「待我處理」入口；依手機選取的 session 或主機可驗證的最近活動排序，不能只靠這台新電腦的瀏覽紀錄。顯示主機、專案、原標題與有文字的狀態，同名 session 可辨識。搜尋/按鈕不依賴快捷鍵。驗收：新 profile 面對 30 條含同名的測試 session，手機剛用的工作在登入後至多兩次操作可到達；沒有待核准時不虛報。
- [ ] **W06 / P0 / Console + 安全 QA：精簡版按實際授權顯示功能。** 公用模式預設只放清單、對話、允許的回覆/中斷/核准、登出；有權限時才出現工作區內的唯讀變更。以 session capabilities 和遠端 scope 的交集為準，後端維持拒絕清單外操作，不能只藏按鈕。驗收：受限帳號不見終端、全機檔案或權限管理，直接打 API 也被拒；允許的回覆真的能執行。全域事件不獲授權時不無限重試，清單仍可更新。代理本身若能執行命令，仍遵守主機核准政策，不能把「沒終端按鈕」當成沙箱。
- [ ] **W07 / P1 / Console：自己的 Chromebook 更像桌面 App。** 沿用 standalone PWA、Ctrl/Cmd+K、深連結、附件與 diff，不另做 extension。測一般分頁和獨立視窗；1366×768 可同時選工作、看最後一則、輸入，多行中文選字 Enter 不誤送。變更欄標成「工作目錄變更」，無權限、非 Git、真的無變更分開呈現。個人裝置釘選或記住上次工作僅在明確選用時啟用；借用模式不記。
- [ ] **W08 / P0 發版門檻 / QA：完整跨端演練。** W01–W06 全過才驗收 MVP。採下面矩陣留下可重現的測試紀錄；現有單元測試不等於外網裝置走查。先對測試主機放行，若失敗，只撤掉新入口或精簡介面的開關，保留舊 Console、手機登入與原有 session。

## 驗收腳本

| 情境 | 通過條件 |
| --- | --- |
| 借來的電腦，無痕或全新 profile，未登入 Google、未裝 Pocket 或 Tailscale | 開固定網址 → 手機掃碼並核准 → 接著同一條對話。建議體感目標：主機在線、手機在手時，5 次中至少 4 次於 60 秒內送出第一則回覆。主機離線另測，不計入正常耗時。 |
| ChromeOS 實機、Windows Chrome/Edge、macOS Chrome；自己的 Chromebook 額外測已安裝的 PWA | Claude Code、Codex 各從原生端建好一條；手機送 A → Web 看 A 並送 B → 原生端回 C；三端順序一致。各做一次核准與拒絕，關 Web 不停止工作。 |
| 壞網路、慢回應、兩個分頁、兩位使用者輪用同一台電腦 | W02–W04 的撤銷、重送、切換、事件補齊全部成立；第二位看不到前一位任何內容。用兩個帳號驗證，不只重新整理同一個登入。 |
| 證據與交付 | 記錄版本、瀏覽器、登入路徑、provider、步驟、耗時與 pass/fail；只用合成對話與去識別的 correlation ID。截圖遮住 QR，勿記 bearer、cookie 或真實工作內容。 |

**開工順序：** QA 先交 W01 路徑與失敗點；bridge 維護者領 W02/W03/W04 的伺服器驗證，Console 前端分批實作；手機端只補現有核准與撤銷畫面的缺口。W05/W06 可用測試資料同步施工。先用借用模式交付，再做 W07。首版不做主機檔案編輯、完整 terminal、PR 管理、多人共編、新的帳號/OAuth 或跨主機搬移執行中的 session。
